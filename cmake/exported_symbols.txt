# The symbols culebra publishes in the executable's ELF dynamic symbol table.
#
# ORC JIT resolves what it emits references to through
# DynamicLibrarySearchGenerator, which is dlsym over the process, so every name
# it can ask for has to be visible here. Those names are exactly culebra's
# C-linkage ones: the `culebra_runtime_*` helpers (jit_mem.h's rt:: family) and
# the `culebra_g_wake` interrupt flag (jit.h's getOrInsertGlobal). The C++ EH
# entry points JIT'd landingpads reference (__cxa_throw, __gxx_personality_v0)
# come from libstdc++.so and are found there, not in this table.
#
# The list is a whitelist rather than -rdynamic-plus-exclusions because what
# leaks out of a statically linked executable is a correctness matter, not a
# size one: an exported symbol here overrides the same name in any library the
# OS later dlopens into this process. LLVM is the live example — Mesa's DRI
# drivers link their own LLVM, and a Canvas window's first GL context bound
# Mesa's LLVM imports to culebra's copy and segfaulted. OpenSSL, zlib and
# cpp-peglib sit behind the same door.
{
  culebra_*;
};
