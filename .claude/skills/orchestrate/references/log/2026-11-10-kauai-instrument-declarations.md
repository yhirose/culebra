# Kauai: instrument declarations, one reading of an entry, a preamble lint, a test audit (2026-11-10)

- 規模: 大。小さな束を4つ(`keys` のつまみ、楽器の宣言、楽器の読み方を1か所に、用語)と、検査1つ、測定1つ。担当(subagent)はコードの見直しだけに使い、実装は直列。
- 見積もり: 楽器の宣言は半日〜1日と見ていて、実績もそのとおり。時間の大半は、`just dev`(約4.5分)の待ち、wasm の作り直し(約6分、`kauai.cul` を直すたびに必要)、着地のゲートでの差し戻し。実装そのものより、直列の資源(ビルド)が支配した。
- 効いたこと: (1) 変更前のバイナリを保存し、同じ曲を recipe で描画して、サンプル数・合計・エネルギーを新旧で比べた(音が変わらないことの根拠)。(2) 簡素化の見直しが、`keys` という名前のつまみで落ちる実バグを見つけた(ユーザーの入力が名前になる表は、オブジェクトにせず配列か反復で読む)。(3) 自己レビューの5つの指摘を、コードで確かめて、半分を撤回した(「`default` は予約語」は思い込みで、実際は `d.default` が使える)。
- 外れ: (1) preamble の局所変数が同名の関数を隠す `ShadowError` を、焼き込みの末尾(約4.5分後)で3回踏んだ(`instrument`、`held`、`within`)。`culebra lint` が同じエラーを0.4秒で出せるので、`just check` の段にした。(2) その新しい検査が、Webview などの任意の名前空間がない CI の軸で「未定義の変数」を報告して、master を赤にした。新しい検査を入れるときは、CI の各ビルド軸(Scene、Webview、Desktop が無い軸)で通るかを先に考える。(3) 再生成した `preambles.gen.h` を、コミットに入れ忘れた(`git add -u` を使えば防げる。`just land` が止めてくれた)。(4) 着地のゲートが、`docs.blocks` の数、`docs/quick-guide` の再生成(公開 API を足したとき)で、1回ずつ止まった。API を足す束は、`just gen-quick-guide` と予算ファイルを、最初から束に入れる。(5) CI の待機コマンドを、あとで消す worktree の中で走らせたので、worktree を消した瞬間に失敗と誤報された(CI 自体は成功)。待機は、消えない場所(main tree)から回すか、終わるまで worktree を消さない。
- 守備範囲の外で回した後処理: `just site-build`(preamble を変えるたびに wasm を作り直す。コミットした wasm が古いと check-playground が落ちる)。
- 組み替えのきっかけ: ユーザーの「もっと構造的でエレガントになるところは?」→自己レビュー→「その指摘をレビューして」→「ROI を調べて」の連鎖で、束の中身が決まった(ミキサーの楽器を同じ宣言の表にする案は、費用に見合わず見送り)。
- テストの棚卸し(「必要以上に大きくなっていないか」): 340本の `--jit` を測った。コストはほぼ全部が JIT のコンパイルで、重複は少なく(40字超の assert 4,693行のうち、同じ行の複製は66)、削る根拠は見つからなかった。分割・統合も効かない(約7%)。唯一の大きな手は、CI の実行の間で JIT のコンパイル結果をキャッシュすること。結果は `project_test_cost_structure_2026_11.md` に残した。
- スキルへの気づき: 「テストを減らしたい」は、削る前に、(a) どこにコストがあるか(`--vm` か `--jit` か、どの機能か)、(b) 冗長の証拠があるか、を測る。削る根拠がなければ、時間を減らす別の手を示す。
