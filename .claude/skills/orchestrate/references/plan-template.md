# 工程表のひな形

仕事ごとに1枚、scratchpadに作る（例：`<scratchpad>/plan-<topic>.md`）。起きるたびに読み直し、状態と実績を書き込む。

```markdown
# <仕事の名前>  （開始<時刻>）

## 目的と完了の条件
- 何が直れば終わりか。着地まで含めるか。

## 作業
| # | 作業 | 誰（自分/担当名） | 資源 | 見積もり | 依存 | 状態 | 実績 |
|---|---|---|---|---|---|---|---|
| 1 | 調査：… | 自分 | なし | 10分 | - | 済 | 12分 |
| 2 | 修正＋落ちるテスト：… | 担当A（worktree …） | ビルド | 40分 | 1 | 実行中 | |
| 3 | レビュー | 担当A | トークン | 7分 | 2 | | |
| 4 | 事前の検証 | 自分 | CI | 35分 | 3 | | |
| 5 | 着地＋push | 自分 | 着地 | 7分 | 4 | | |

クリティカルパス：1 → 2 → 3 → 4 → 5、見込み 約100分（完了予定<時刻>）
並列案との比較：<並列にした場合の見込みと、選ばなかった理由>

## userに聞くこと（先に聞く）
- …

## 走っているもの（台帳）
| 種類 | ID・名前 | 何を待つか | 期限 | 起動時刻 |
|---|---|---|---|---|
| 担当 | <agent id> | 修正 | 見積もりの1.5倍= <時刻> | |
| バックグラウンド | <task id> | 見回り（sleep 900） | 15分 | |
| CI | <run id> | 事前の検証 | 50分 | |
| user | - | userの確認（渡したもの） | なし（待つ間は他を進める） | |

## 組み替えの記録
- <時刻> <きっかけ> → <変えたこと>（理由）
```
