# 2026-11-10 Culebra の関数を別のスレッドから呼ぶ試作（着地なし、測定のみ）

- 見込み: ビルド4回（`bindings.h` の変更ごとに約5分）と測定。実際: ビルド4回、測定は小さなスクリプト4本。
- 方針: `JIT::run`/`exec` は値を返さず、終わると LLJIT を破棄する（調査役の読み）。実行後に関数は取り出せないので、`bindings.h` に実験用のネイティブ関数（`_Audio.kernel_bench/kernel_start/kernel_stop/kernel_block`）を足し、スクリプトの実行中に受け取った `JitClosure*` の `fn_ptr` を `std::thread` から直接呼んだ。パッチはコミットせず、scratchpad に保存して `git restore` した。
- 呼び出し1回（sin 1回、1000万回、`just build`）: 呼び出しのスレッド 型なし17.4 ns・型付き37.5 ns。専用の Runtime を持つスレッド 15.5 ns・32.9 ns。素のスレッド 15.4 ns。ループ中の malloc は全て0回（`malloc_logger`）。
- 主スレッドが同時に動く場面（外部スレッドが0.2〜5秒呼び続ける）: 専用の Runtime では、待つ・確保とGCが重い・同じ関数を同時に呼ぶの全てで答えの誤り0、クラッシュなし、関数の参照カウント不変。最大の遅れ（64回の塊）は0.04〜0.84 ms で、待つ場面と同じ頻度の外れ値。素のスレッドは、主スレッドの確保が重いと最大11.4 ms。専用の Runtime が必須。
- ブロック形（型付き `fn (out: Array, count: Long, start: Long, f: Float) -> Long`、128サンプル、1000万サンプル）: 外部スレッドで4.3 ns/サンプル（C++ は3.9 ns）。結果をホストが `JitArray::items[i].data` から直接読んで `std::sin` と比べた誤りは0。配列は呼ぶ前に参照カウントを +1 して渡すと、呼んだ後に元の1へ戻る。確保は、最初のブロックで1〜2回、以降の78124ブロックで0回。あらかじめ作った Runtime を主スレッドで温めても、最初のブロックの確保は1回残る（スレッドごとの初期化とみられる）。
- 例外: 投げる関数を外部スレッドで呼ぶと、プロセスごと落ちる（終了コード133）。呼ぶ境界で例外を受け止める仕組み（`culebra_runtime_call_from_host` など）が要る。受け止めて動くかは未確認。
- 見落とし: 試作は macOS だけ。Linux、Windows、AOT、WASM、LLJIT や関数の寿命（グラフより先に解放されると危険）は未確認。
