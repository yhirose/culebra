# Audio.harmonics の窓を整数周期に（2026-11-19）

- 規模: 小〜中（中心ヘッダ audio.h の1関数、テスト、docs、wasm の作り直し）。worktree 1本、担当なし（計画レビュー1人、/simplify 3人）。
- きっかけ: Studio の倍音グラフで 80 Hz 未満の倍音比が崩れる（既知の制限）。user が「整数周期の窓」（お奨め）を選んだ。
- 測ったこと: 20 ms の窓は周期の整数倍（2以上）のときだけ正確（100、150 Hz）。のこぎり波の最大誤差は 110 Hz 0.58 dB、80 Hz 2.5 dB、55 Hz 23〜48 dB。numpy の試算で案を比べた（切り上げ、最低3・4周期、100 Hz 未満だけ）。切り捨て・最低2周期が、どの高さでも誤差0、高さの推定が5セントずれたときも今以下。
- 計画レビューで変えたこと: 位相を区間をたどって積み上げる一般形は、隣の中心から先で隣の高さを保つ単純な形と差が測れなかったので、単純な形にした。テストの境界（低いビブラートの残り < -55 dB）は高さを追わない変異で落ちる位置に置いた（レビュアーの numpy の写しは dev ビルドと 1e-3 dB まで一致）。音の出だしの区間の境界を 0.7 → 0.8 dB に（新しい窓で 0.691）。wasm の作り直しが要る（CI の playground-smoke とページは commit された wasm を使う）。
- 実績: dev 2回（各約5分）、site-build 2回、just check 2回（28〜34 s）、doctest、check-playground、check-generated、studio_test。/simplify の3件（窓の形と隣までの距離の重複、位相の計算を1回に、テストの確認を `reads` に）は、直す前後で出力がビット単位で同じ。
- 費用: tests/test_audio_harmonics.cul は executor 0.09 → 0.13 s、JIT 1.23 → 1.67 s。10 s の 41 Hz ののこぎり波で、倍音の分は 0.24 → 0.48 s（音の高さの推定は 0.88 s のまま）。
- 気づき: worktree のガードが、git を含む複合コマンド（変数、`&&` で git と別のコマンドを繋ぐ）を拒むので、submodule の初期化が抜けたまま bench を回して1回落とした。セットアップは単独のコマンドで、最初に済ませる。
