# 2026-11-12 パイプ `|>`（P3）

- 見込み: M。実際: 文法、脱糖、フォーマッタ、エディタの文法4つ、docs（言語、内部、エッセイ、クイックガイド）、CLAUDE.md。ビルド4回。
- 形: `a |> f(b)` は `(a).f(b)`。文法では比較のすぐ上（ビット演算、範囲、算術より下）の段 `PIPE`。右辺 `PIPE_STEP` は `.名前(引数)` の連鎖と同じ節点（`@name` の `AT_MEMBER` と同じく、名前を DOT として読む）。脱糖 `desugar_pipes` が、`|>` ごとに、左辺を頭にした `CALL` を組む。括弧で書いた `(a).f(b)` と同じ形なので、名前の探し方（メソッド、次に UFCS）も、`?.` の短絡の範囲も同じ。`BIT_OR_OPERATOR` は `|>` を取らない。行頭の `|>` は前の行に続く。
- 誤り: `a |> f`、`a |> f() * 2`、`a |> (f())` は文法の段階の構文エラー。ラムダの引数の既定値の中では、むき出しの `|` と同じく括弧が要る。
- フォーマッタ: `PIPE` を二項演算子の鎖に入れ、優先順位の表に段を足した。既定値の中の `|>` に括弧を残すよう、`|` と同じ扱いにした（`fmt_test` のコーパスの往復で見つかった）。
- 方針の転換: CLAUDE.md の「`|>` は追加しない」を、書き分けの目安に置き換えた。エッセイ（llm-first）の「パイプ演算子はない」の段落も、優先順位の低い `.` として入った経緯に書き直した。
- /simplify で見つかったバグ: 構文木の最適化で親（添字の `[ ]`、括弧、1文のブロック）が畳まれた節点は、親の元の名前と範囲を持つ。脱糖がそれを捨てたため、`xs[1 |> f()]`、本体が1つのパイプの `handle`、括弧つきのパイプと `perform` が落ちた。既存の `desugar_is_test` も同じ形（`m[1 is Long]`）。`SynthNode::replacing` で「置き換える節点は元の名前と範囲を受け継ぐ」を1か所で保証し、両方に使った。フォーマッタは、`is` の左辺の優先順位、パイプの右辺の連鎖の折り返し（`print_call` から `print_chain` を切り出して共有）、折り返しを行頭の `|>` にそろえた。
- P2 の CI の失敗（同じ着地で直した）: 問い合わせ口を、参照されない inline 変数の初期化で入れていたため、Windows の AOT ビルドでリンカに捨てられた。各ホストが標準ライブラリを用意する場所で `install_namespace_members()` を呼ぶ形にした。`infer_test` は標準ライブラリなしでコーパスを測るので、`{*}` で拒まれるファイルは構文エラーと同じく飛ばす。
- テスト: `tests/test_pipe.cul`（VM と JIT で同じ）、`tests/lint_test.sh` に構文エラー3件。畳まれた節点の確認は、修正前のビルドで落ちることを見た。
