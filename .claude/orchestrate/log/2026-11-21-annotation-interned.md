# flight-break#91: クラス名の型注釈の引数が、呼び出しのたびに約50ns余計にかかる

- 規模: 中。直列、担当なし。30行を超えるので、着手前に見積もりを出して user が進めると決めた。1段目の後、2倍に届かなかったので user の指示で2段目まで。
- 直し方: 1段目は、フィールドの注釈を一度だけ読む仕組みを `TypeAnnotation` に広げ（ユニオン、`T?`、関数型、クラス名と列挙型名のポインタ、`exact`）、1つだけのオーバーロードのゲート、UFCS、フィールドの書き込み、`ChkArg`／`ChkTypeAt` が同じものを読む形。JIT と AOT は検査の場所ごとに空の欄を持ち、最初の検査で埋める（番地を焼き込まない）。2段目は、注釈のある1つだけの `fn name` も呼び先を決めて（`Reach::MonoGated`）、ゲートを聞いてから本体へ直接入る形。`Any` は検査もゲートも出さない。
- 実測（just build、JIT、1回の呼び出し）: `Box` 87 → 10.3 ns（注釈なし 5.3 ns、1.9倍）、`Box?` 168 → 10.9 ns、`Any` 24 → 5.35 ns。VM は `Box` 125 → 43 ns（注釈なし 37 ns）。最初の just build は、メモリ不足で Claude Code に止められた。
- テストの効き目: 足したテストは振る舞いを保つ確認なので、修正前でも通る。ゲートを素通しにする改変で、再帰と外れの確認が両レーンで1件ずつ落ちることを確かめた。速い道と文字列での照合や picker との食い違いは assert で見張り、linux-assert だけが回す。
- 落ちた検査: check-generated の borrowed-closure-door（vm.h の生のキャストが 13 → 14）。`mono_callee` の中でゲートを聞く形にして本数を戻した。
- /simplify（4観点）: 判定の3段を `_culebra_annotation_decides` に、近道の要否を `mono_needs_gate` にまとめ、入口の確認の前のタグの飛び越しを覚えた注釈から出し、ゲートと呼び出しで引数の配列を共有。見送り: 注釈の文字列を読む処理が5か所ある件（全部を覚えた注釈の上に作り直すと250〜350行）、ゲートの後に本体の入口の確認がもう一度走る件（残りの約5 ns の大半）、`Long | Any` の `Any` の扱い（照合器と picker で答えが違い、揃えると振る舞いが変わる）。
