# 2026-11-12 Audio の「式の層」の試作を広げる（着地は記録のみ）

- 見込み: 最新 master のビルド（ccache）と、Culebra のスクリプト約550行、数時間。実際: ビルドは短く、スクリプトの直しが、設計の発見を含めて4回。
- 内容: 前回の試作に、`feedback`、多チャンネルの展開（`Bundle`）、`control` と `set`、`Env` のカーブ、`play` の自然な終わり（`end_time`）、`Voices`（固定の `Audio.Graph` に声のスロットを先に作る形）を足し、21の確認をした。手書きの Graph との差、DFT での音の高さの強さ、無音になる時刻で見た。`culebra` と `--jit` の出力は、完全に同じ。
- 結果: `feedback`、`Bundle`、`control`、自然な終わりは、手書きの Graph と一致（差 0.0、終わりは 1.01 秒と 0.8 秒）。`Env` のカーブは、20区間以上の折れ線で誤差 0.5% 以下。`Voices` は、4音の連続、最も古い声の奪取、`Env.adsr` のリリースが成り立つ。
- 設計の修正: (1) `Voices` の builder は、ノート番号でなく周波数（Hz）を受ける。今の Graph は鳴らし始めたあとに部品を足せず、`hz` は非線形で部品にできないため。(2) `Env` は声ごとのテンプレートで、`note_on` のたびに `cancel`、`set`、`ramp` を再生する。(3) 声の待機の値は、`Env` の最後のレベル。最初のレベルだと、最初のノートの前に鳴る（試作のバグで、最初の検出は、2音目を前の音の有無で比べたときだった）。(4) 声は使い回しで、弦やフィルタの状態が持ち越される（2音目の RMS の約4%）。(5) 下限のある値（`pluck` の freq は 20 Hz 以上、`filter` の cutoff は 0 より大きい）に信号を渡すときは、基準値を下限にして、同じ値を定数で引く。
- 範囲の見直し: 新しい音源（`impulse`、`dust`、`lfnoise`、`pulse`）は、今の Graph の部品では作れず、エンジンに C++ で部品を足す別の仕事。式の層が前処理だけで書ける範囲は、今の部品で組める式まで。
- 教訓: 試験が通っても、待機の状態（最初の音の前）や、状態の持ち越しのように、試験の窓の外に出る挙動がある。窓の外の挙動は、「前の音がある場合と無い場合の差」のように、対照を作って測る。
- 見落とし: `.range`、`.decay2`、`.lag`、`.pan`、`Env.adsr` の `Voices` 外の使い方、実デバイスの再生は確かめていない。
- 後処理: 着地は記録のみ。試作のコードは、リポジトリに入れていない（scratchpad）。
