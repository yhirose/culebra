# 2026-11-09 Audio.Graphのループ(再設計の段階2: 任意の部品から`connect`、ループはdelayを通す)

- 規模: 大(`audio.h`の`Graph`の計算順の作り直し、recipeエンジンの2段階化、wasm、docs 英日)。実績は計画のレビューから着地まで数時間。
- 時間の行き先: `audio.h`のビルドが約4分×6回(実装後、性能の実験、Block/Sampleの取り違えの修正、変異ビルド、変異を戻した再ビルド、`order()`の分割)、wasmの再ビルドが2回(Block/Sampleの修正の後と、`order()`の分割の後)、`just build`(リリース構成)が1回。検証一式を、修正のたびにやり直した。
- つまずきと、見つけた方法:
  1. recipeの順序付けに穴があった。深さ優先探索が緩い辺をたどった先で、通常の辺から開いたままの部品に当たり、正当なループを誤って拒否した。テスト(`wobble`)を書いて初めて気づいた。計画のレビューでは見つからなかった。作る順は通常の辺だけで決めて、緩い辺は到達の検査にだけ使うことで直した。
  2. ループなしのグラフが+10%遅くなった(7.65 → 8.45us/ブロック、`-O3`、ヘッダー単体、7回の最小)。原因は、ブロック経路のオフセットがコンパイラに定数0と分からなかったこと。`phase`をテンプレート引数にしても効かず(分岐ではなかった)、ブロック経路で`a = 0`を明示して、7.80usまで縮んだ(`__restrict`は効かず、戻した)。切り分けは、全ツリーのビルドを待たず、ヘッダー単体のベンチを段階1のヘッダーと比べて行った。
  3. `Whole`が「ブロック全体」と「ループ内の通常の部品」の2つの意味を持っていた。性能の修正で、前者のオフセットを0に潰したら、後者(ループ内のgain・filter)が位置0を見て、エコーが壊れた。`Block`と`Sample`に分けて直した。全ツリーのビルド(約4分)の後にグラフのテストが落ちて気づいたが、単体の`loop_check`を回していれば、ビルド前に分かった。
- 効いた検証: 834ケースのビット比較(ループなしの全recipeが、作る順の変更と後張りの導入を経ても一致)、`audio_engine_test`の再生と描画の一致とヒープ確保なし、変異ビルド(1サンプルの下限を外す、NaNの丸めを外す、`settled`を元に戻すの3つ。各assertが単独で落ちる)。ループ内のdelayをブロック計算に変える変異でも、`audio_engine_test`が14850サンプル目から落ちた。
- 見落とし(自分の誤り): 計画のレビューを担当に出したあと、私がworktreeを消したため、担当のBashが使えなくなり、部分的なレビューになった。担当が動いている間はworktreeを消さない。
- 着地の詰まり: ゲートの数の上限(`gate_budget.txt`の`docs.blocks`)が、新しいdocsの例2つで1164 → 1166になって止まった。理由を添えて更新する決まりがあり、テストの時間も測った(グラフのテストは約0.50 → 0.52秒、C++のunitテスト全体で0.14秒)。docsに実行される例を足すと、予算の更新が要ると、計画の段階で数えておく。
- CI: 段階1と、他セッションのコミットのCIが、GitHub側の`504`(依存の取得)で落ちていた。コードの失敗ではないと、ログで確かめた。段階2のCIは全ジョブ成功。
- スキルへの気づき: 中心ヘッダー(`audio.h`など)を触る仕事では、全ツリーのビルドの前に、そのヘッダー単体で回せる確認(出力のハッシュ、期待値、速度の比較)を用意して先に回す。ビルドが約4分かかるので、1回の取りこぼしが数分ずつ積もる。
