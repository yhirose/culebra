# 2026-11-12 Synth の Voices（P6）

- 見込み: M。実際: `synth.cul` に約200行、テスト、docs の46節。ビルド2回。
- 内容: `Voices(count, |freq| 式)`、`note_on`／`note_off`／`sequence(notes, step, len, at)`／`ends`／`now`。`play` と `render` が `Voices` を受ける（`wait: false` なら止めるまで鳴る）。
- 設計: `Voices` はノートの記録を持ち、`render`／`play` のたびにグラフを作って記録を流し直す（式と同じく記述であり、どのサンプルレートでも描ける）。鳴っている間のノートは、鳴っているグラフにも入れる（その時計に合わせる。P4 の `set` と同じく、cancel の着地点から始める）。声が空く時刻は `ending(expr, held)` で、自然な終わりの規則（遅延や弦の余韻も）をそのまま使う。`ending` には、ゲートつきのエンベロープを離す時刻だけを足した（`.hold` を通す）。声のエンベロープかどうかは、その値を持つ部品が builder の中で作られたか（番号が声の `freq` 以降か）で決め、全声で共有する部品のエンベロープは先頭から動く。
- 計画からの変更: 「待機の値はエンベロープの最後のレベル」をやめ、声ごとのゲート（最初のノートまで 0）にした。変異で、待機の値がゲートのもとでは観測できないと分かったため（仕組みが1つ減った）。奪う声のフェードは 5 ms で、新しいノートはその後に始まる。
- 見つけたこと: モジュールを利用者のコードとして JIT にかけると、それだけで P5 で 6.6 秒、P6 で 8.8 秒かかる（連結した確認用のファイルの場合）。焼き込んだモジュールでは、この費用はかからない。
- /simplify: 品質で効いたのは2件。(1) 声ごとに最後のノートしか持たず、後の時刻のノートを先に作ると、前の時刻のノートを作ったときの cancel で消えていた（同じ時刻から始まる2つの `sequence` を重ねると、最初の音が消える）。「時刻順に作れ」と拒む案もあったが、重ねるのはふつうの使い方なので、構造で直した: 声ごとにノートを区間で持ち、イベントは時刻順に挿入し、鳴っているグラフには、挿入したノートの後のその声のイベントを当て直す。声の選び方は「鳴る間ずっと空いている声」→「始まる時点で無音の声（次のノートの前の 5 ms でフェードして切る）」→「鳴っているノートがいちばん早く始まった声を奪う」の3段にした。(2) 待って鳴らした `play` を、鳴っている一覧に入れていたので、デバイスなしで 65 回目にグラフの上限に当たった（待たない `play` だけを入れ、終わったものは1か所で手放す）。重複は、離したときの下がり方を `hold` から読む、`schedule` を使う。効率の「曲線を毎回20本のランプで送る」は、値に複数の変化をまとめて渡す公開 API の追加が要るので P8/P15 へ回した。
