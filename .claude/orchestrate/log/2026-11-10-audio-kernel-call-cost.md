# 2026-11-10 Culebra の関数をオーディオ処理の核にする案の、呼び出し費用の測定（着地なし）

- 見込み: `just build` 約400秒 + 測定コード。実際: ビルドは約400秒（他のセッションの待ちなし）、測定は4本のスクリプトと C++ の基準で、合計1時間未満。
- 方針の変更: 埋め込み API（`vm::Embed`）の `eval`/`call` は VM のセッションで、JIT した関数のポインタを取り出す入口ではなかった。C++ から関数ポインタを呼ぶ当初の測定は取りやめ、`--jit` の中で関数を値として渡し、間接に呼ぶ形（箱入りの呼び出し規約）に切り替えた。
- 測定（`just build`、`-O3` と LTO、sin 1回の計算を1000万回）: C++ は1回3.9 ns。JIT のインライン展開は3.9 ns。間接呼び出しは型なしが19.9 ns（+16 ns）、型付きが41.6 ns（+38 ns、引数の型検査が約22 ns）。VM は64 ns、112 ns、128 ns。
- ブロック形（1回の呼び出しで128サンプルをループ、1000万サンプル）: 型なしの引数は12.7 ns/サンプル（インラインのループは4.4 ns）。引数に型（`Array`、`Long`、`Float`）を付けると4.2 ns/サンプルで、C++（3.9 ns）と同じ。VM は約61 ns。
- 結論: JIT した型付きのブロック形の関数は、C++ と同じ速さで動く。サンプルごとに呼ぶ形は、箱入りの呼び出しが重い（型付きは特に）。呼び出しの費用はブロック形で薄まる。
- 残った未確認: オーディオスレッドから JIT した関数を呼べるか（スレッド状態の遅延確保、GC、例外）、ブロックの入出力に `double[128]` の生のバッファを渡す方法（Culebra の `Array` は boxed）、既定の実行が VM のときに JIT をどう使うか、AOT と WASM のレーン。
