# 2026-11-13 Synth P13: ステレオと .pan

- 規模: 大（エンジン・bindings・前処理・テスト・docs、音声スレッドの変更で着地の前に ci/ を待つ）。計画 → 独立レビュー1回（10件すべて採用） → user の確認（推奨どおり、細部2つ） → 実装 → /simplify → ci/ → 着地。
- 見込みと実績: 見込みは約5.5時間（dev 278秒×2〜3回、CI 約35分）。実績は dev 2回（実装をまとめて1回、/simplify の後1回）。C++ を直すたびに組むのをやめ、エンジンの確認はビルドの前に、試作の形（master と新しいヘッダの写しを同じ駆動で組んで流れを比べる）で済ませた。
- 計画のレビューで見つかったこと: 左右のフェーダーやゲートを値2つにすると、鳴っているグラフでは cancel のたびに binding がデバイスの時計を読み直すので左右がずれる（render では時計が NaN なので見えない）。予定を入れる値を1つにして、2本のときは level を各チャンネルの gain に connect した。ほかに、`Sound.new([])` の扱い、エンジンのテストのフレームの数え方、実機のコールバックが左右で半分のフレームになること、登録表の引数の数、エラーの順、WAV の rate の上限。
- 測ったこと: モノの音は左右とも master とビット一致（曲と残響、tone、Graph、ループ、142077 フレーム）。費用は旧1024／新512フレーム刻みで +2.7〜2.9%（3回）。ビルド中に測った回は +2.9% 前後に揺れたので、比べ直しはマシンが空いているときに。
- テストの効き目: エンジンは変異2つ（右の和を左から、Room を右に足さない）で落ちる。Synth は前処理を焼き直さない変異の写し（P11 の形）で17通り、すべて落ちる。`cos` で書くと端が 6e-17 になり「端がちょうど 0」の確認だけが落ちる。
- /simplify（3人）: 12件すべて採用。`.pan` は `self * pan_gains(pos)` で node の多チャンネル展開に任せる、エンジンはいつも右も描く（モノを両方へ出す判断は Graph の1か所。費用は +0.5% ほど増え、試作の値に戻った）、`channels_or_one`、`get(i, fallback)`、`controls` の重複、テストの gc-stress（1サンプルごとの `sweep.at` が重く、3つの実行で 19 → 14 CPU 秒）。
- 組み替え: 計画は2コミットだったが1つにした（`preambles.gen.h` と docs が両方の変更を抱え、途中のコミットを生成物の検査に通すには焼き直しがもう1回要る。CI は先頭だけを回す）。
- 着地の前: origin/master が別のセッションの push で2つ進み、ローカルの master（未 push の記録 4344473e）と分かれていた。worktree の中から main tree を触れない（安全装置）ので、ブランチを origin/master に rebase し、worktree を出て main tree の master を、中身が同じ載せ直した記録のコミットへ `reset --keep` で移してから ci/ に出した。
