# 2026-11-12 Synth P11: Proxy v1（鳴らしたまま音を入れ替える箱）

- 規模: 小（1領域、担当なし、着地の前に重い後処理を待たない）。計画 → 独立レビュー1回 → user の確認（仕様4つ） → 実装。
- 見込みと実績: 見込みは実装・テスト・docs 60〜90分、dev 3〜4回。実績は dev 5回（変更前の基準1、実装の初回は前処理の名前の衝突で失敗1、実装1、要らない分岐の削除1、/simplify の後1）。
- 仕組み: 待たない再生の方式（P4、音量 0 にして次の play で手放す）に揃えた。play はいつも出力の後ろに音量の gain を1段置き、handle がそれを持つ（`_fade_in`、`_end`）。play の `secs` も `_end` で書き直し、標本が変わらないことを確かめた。
- 計画のレビューで見つかったこと: fade 0 で `_end` を鳴っているグラフに使うと、ramp が cancel の着地点（今の時計）より前に入り、旧い音が全音量に戻る（再現した）。control の `set` と同じく、cancel の後に時計を読む形にした。/simplify で、この手順を `_move` の1か所にまとめた。
- user が決めたこと: 自然な終わりのない式だけフェードインする（自分で終わる式は立ち上がりを保つ。参照した他の処理系と同じ）、`stop()` もフェードアウト、曲線は直線、既定の fade は 0.05 秒。
- テストの効き目: 前処理を焼き直さずに変異を回した。変異を入れた synth.cul の写しの名前空間を別名にしてテストの前に連結し、assert ごとに合否を出す（18通り、1通り 0.2 秒）。どの変異でも落ちない確認から、前提だけの確認を1つ消し、要らない分岐（fade 0 のときのフェードインの省略）を1つ消した。
- テスト時間: test_synth_proxy.cul は VM 0.21 s、JIT 3.7 s。`just check` 27 s（予算 23 s、この変更の前から超えている）。
- /simplify: `assert_throws(..., message:)` に揃える（2人が同じ指摘）、`set` と `_end` の時計の扱いを `_move` に、オブジェクトの省略記法、後置 `if`、`ends()` のコメント。効率の指摘は0件（gain 1段の費用は無視できる、gc-stress のレーンでも数秒）。
- push 後の CI: test-macos の掃引で test_synth_proxy.cul が落ちた。「フェードインの途中で set」の確認が、`Time.sleep(0.03)` の後もまだ 0.1 秒のフェードインの途中にいる前提で、負荷の高いランナーでは 0.144 秒眠り、期待値 `cut / 0.1` が 1 を超えた。眠りを 0.15 秒にした写しで手元でも再現した。フェードを 1 秒にし、押さえた値を `min(cut / fade, 1)` にして、眠りが延びても成り立つ形に直した。壁時計を使う確認は、眠りが延びた場合を最初に考える（全部の眠りを 0.15 秒にした写しで回すと安く分かる）。
- その修正の CI: 今度は Ubuntu の gc-stress で、Voices のノートが箱に届く確認が落ちた。「いま」に置いたノートを、後で読み直した `now()` から探していて、遅いレーンでは2つの呼び出しの間にノート（約 0.05 秒）が終わっていた。眠りだけでなく、文と文の間の時間にも頼っていた。トップレベルの文の後ろにすべて眠りを挟む写し（0.15 秒、0.5 秒）で再現し、ノートを 1 秒先に予約して、その時刻から数える形に直した。眠りの写しでは足りず、文の間を伸ばす写しが要る。
- 気づき: 前処理の関数名と同じ名前のローカル変数は、焼き込みの時点で ShadowError になる（`level`）。変異の写しで `let {*}` は使えない（焼き込んだ名前空間だけ）ので、名前を並べて取り込む。
