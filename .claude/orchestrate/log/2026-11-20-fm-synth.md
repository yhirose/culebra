# 2026-11-20 examples/fm-synth と Synth.velocity（大）

- 作業: 3オペレーターの FM シンセ（Desktop、MIDI 鍵盤と EWI、プリセット、AOT で 10 MB）を 57c96fc2 で着地。続けて、プリセットを選んだ直後の最初のクリックが無音になる件とエンベロープを離したら反映（ff5b39f2）、`Synth.velocity()` と Touch（b9cf505b）。
- user の決定: 画面は Desktop、FM は2〜3オペレーター、EWI はモノの声を別に、「わかりやすく操作しやすく」。ベロシティはビルダー内の `velocity()`、アプリは Touch つまみ1つ、エンベロープは離したときに反映（C）。
- 後処理: /simplify は3回（初版は3観点の担当、のちの2回は1担当）。初版のレビューで、保存したモードを切り替えられない・機器を抜くと音が残る・名前の衝突・範囲の食い違い・Shift で鳴りっぱなし、を直した。
- 組み替え: user の「切り替え後に1秒待たされる」は、エンジン・通信・グラフの実測（どれも数十 ms 以下）で外側と分かり、ページのイベントに時刻を付けて user に実機で回してもらって特定した（WKWebView が <select> のメニューの後の最初のクリックに pointerdown を出さない）。推測で直さず、計測版を作業用フォルダに作ったのが早かった。
- 新しい問題: `velocity()` の最初の案（モジュールの可変状態）が、Http ワーカーへの送信で状態が分かれて壊れた。別の件として memory（project_closure_send_splits_shared_state）に記録し、設計は既存の `owned()` を使う形に変えて状態をなくした。
- 着地の止まり: sandbox 内の `just land` が mktemp で落ちる（memory どおり sandbox 外で回す）。1回は1セッションの全テスト掃きで1ファイルが落ち、同条件の再実行で緑（負荷の偽の失敗とみた）。ゲートの再現は `CULEBRA_CANVAS_HEADLESS=1` を付けないと Canvas が別物になる。
- 気づき: プリアンブルの関数の引数名とモジュールのトップの名前は同じにできない（shadow エラーが焼き込み時に出る）。焼き込みの失敗は `just dev` のログで初めて分かるので、プリアンブルの変更は早めに1回焼く。
