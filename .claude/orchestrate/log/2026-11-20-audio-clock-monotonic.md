# 2026-11-20 Audio のストリームの時計が戻らない（小）

- 作業: examples/fm-synth/engine/test_engine.cul が音の出口のある Mac で時々 `a change's time is 0 or more` で落ちる件。根は Engine::stream_now() が、遅れたコールバックの後に戻ること（その隙に始めた graph の now が負）。stream_now を前に返した値より戻らない形にし、tone() だけの守り（last_start_）を消した。
- 見込みと実績: 根の確定まで約30分（memory に残した見立てがそのまま当たった）。修正と確認で約1時間。
- 確認: 実機で同じ時間帯に交互に100回ずつ、修正前16回、修正後0回。エンジンの単体テスト（偽の時計）に 50 ms 遅れたコールバックを足し、修正前のヘッダーで「0 から -0.05 秒へ戻る」で落ちることを確かめた。
- 道具: audio_engine_test はヘッダーだけなので、submodule の初期化を待たずに、初期化済みの worktree の vendor を -I で借りて c++ で直接ビルドできた（修正前後の比較もヘッダーを別のフォルダに置いて）。
- /simplify: 2担当（効率は、主スレッドのロック中の比較1回だけで音声の描画に触れないので省いた）。採ったのは古い説明2か所と変数名（latest_now_）。
- ci/ は通さない: 主スレッド側の時計だけで、全 OS の CI は master の1回で見る。
