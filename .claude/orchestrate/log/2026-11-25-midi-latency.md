# MIDIのキーから音までの遅延を測る道具（#30の2、2026-11-25）

- 規模: 小（examplesだけ、エンジンは変えない）。計画をuserに見せて「おすすめで」。
- 作ったもの: `examples/midi-latency/`。マイクを鍵盤のそばに置いて10回叩くと、1本の録音の中の「コツ」と鳴らした2 kHzの正弦波の開始の差を出す。録音（`Audio.Capture`）はサンプルに時刻を付けないので、MIDIの時刻と録音を同じ時計で比べられない。同じ録音の中の差にすれば、マイク側の遅れは打ち消し合う。検出は`onset.cul`に分けた（1 msごとのGoertzelで正弦波が8窓続く最初の窓、その前の0.1秒で静かな所の4倍と0.02を超えた最初のサンプル）。
- 確かめ方: `test_onset.cul`は答えの分かる合成の録音（小さなhiss、3 msで消える「コツ」、遅らせた正弦波）で4 ms・12.3 ms・30 msを1.1 ms以内に当てる。検出の5か所をわざと壊す確認で全部落ちることを見た。最初は「続く窓の数を1にする」壊し方が生き残った（「コツ」が正弦波より小さかった）。実際はマイクが鍵盤のそばで「コツ」のほうが大きいので、テストの録音をそれに合わせて落ちるようにした。本体は`CULEBRA_AUDIO=off`で「MIDI入力がない」の分岐まで。実機での計測はできていない（WSLにMIDI機器がない）。
- 気づき: Long同士の`/`は整数の割り算（`7 / 2`が3）で、空のArrayの`min`は例外。`let {*} = NS`はブロックの先頭にしか置けない。どれも動かして初めて分かった。
