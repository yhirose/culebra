# 2026-11-12 Voices の記帳の2乗を直す

- 規模: 小（synth.cul の SynthVoices とテスト）。見込み: 1時間強（推定）。
- きっかけ: P8 の測定で、`sequence` の1ノートあたりが 250/500/1000 ノートで 53/80/128 us（VM、`just build`）と伸びていた。`note_on` が全ノートを、`note_off` が全ノートを、`ends()` が全ノートを、`_add` がイベントを後ろから1つずつたどっていた。
- 直し方: 1つの声のノートは重ならない（次のノートの始まりまでに終わる）という性質を、不変条件として保つ。声ごとのノートを開始順に置けば、空いているか・鳴っているノート・次のノートは二分探索1回で分かる。`note_off` はノート番号ごとの一覧から、`ends()` は各声の最後のノートから、`_add` も二分探索で入れる位置を決める。不変条件はテストで実行して確かめる（`assert_voices_ordered`）。
- 自分の誤り: (1) 編集の後に `misc/gen_preambles.sh` を回さずに `just build` し、古いモジュールで測った（数字が変わらず、新しいテストが落ちて気づいた）。`src/preambles/*.cul` を変えたら、ビルドの前にヘッダーを作り直す（`just dev` は作り直すが、`just build` は作り直さない）。(2) 「自然に終わらない声のノートだけ一覧に入れる」と最適化したが、`perc * adsr` のように自然に終わるがゲートつきの声で `note_off` が効かなくなった（レビューが見つけた）。
- /simplify（2本にまとめた）で直したこと: 同じ時刻やフェードの途中に2つ奪うと、新しいノートが次のノートの後ろの位置に入り、順が崩れて `ends()` が誤った（フェードを次のノートで止め、入れる位置は `t` で決めて、不変条件を構造で保つ）。60 と 60.0 の鍵が別だった。開始が同じノートのどれを離すかを、前と同じ声の順に戻した。一覧から外す道を1つにし、イベントのたびのクロージャーを外に出した。
- 確かめたこと: 変異16件すべてで落ちる。品質レビューのランダムな比較（300通り、時刻の順と順でない作り方、3種類の声）で、今のモジュールは300通りすべてで不変条件を保ち、前のコードが整合していた46通りでは前と完全に同じ。前のコードは、2 ms おきに奪う場合などに、ノートが重なる不整合を起こしていた（これも直った）。
- 結果（`just build`、P8 の m2.cul、同じマシン）: `sequence` の1ノートあたりが 250/500/1000 ノートで 31.7/31.4/35.8 us（VM、前は 53/80/128）、15.4/13.9/17.2 us（JIT、前は 20/26/34）。5000 ノートでも 36.6 us（全体 0.18 秒）。グラフを作るときの1ノートは変わらず（曲線 71 us、直線 22 us、VM）。
- テスト時間（`test_synth_voices.cul`、dev の -O1）: VM 0.2秒のまま。JIT は 4.6→6.6秒（足した約60行のコンパイル、ファイルの予算 60秒）。gc-stress の refs-jit の脚は 24→32秒（予算 44秒の 73%。CI は最適化ビルドなので速い）。次に Voices のテストを足すときは、別のファイルに分けることを考える。
- 残したもの: 鳴っている間に、先に予約したノートより前の時刻のノートを作ると、`_add` が後のイベントを全声分たどる（予約したイベントの数に比例）。声ごとにイベントを持てば消えるが、長い曲を予約した上で鳴らしながら弾く使い方が出てから。
