# Page.socket とブラウザの FM Synth（段階3）

- 規模: 大（ci/ を待つ）。直列、担当なし。/simplify の3人だけ並列。着地 7712c294（ci/ で全28ジョブ緑、そのまま早送り）。前のセッションの WIP（未ビルド）を引き継いだ。
- 見込みと実績: 見込みは「ビルド→site-build→テスト→docs→/simplify→実機→ci/→着地」の順。実績もその順だった。dev の作り直しは3回（WIP、コメントの修正、/simplify の後）。中心ヘッダなので1回約5分。wasm は5回（初回、変異2回、戻し、/simplify の後）で、1回約2分。
- 計画で効いたこと: WIP を読み直した段で、page_web.h の receive が設計（ページか MIDI のどちらかで起きる）と違うことに気づいた。タイムアウトまで待ち続けていたので、ビルドの前に直した。
- 組み替えのきっかけ: /simplify で2件見つかった。どちらも、ページの開閉の状態を1つしか持たないことが根だった。①開き直したあとに古い値を drop すると新しいソケットを閉じる ②ページが去ったあと開き直せない。1件ずつ直さず、セッション番号の形にして2件まとめて閉じた。開き直しの扱いは docs の文面に合わせて決め、user に報告した。
- 守備範囲の外で回したもの: 変異のビルドを wasm で2回。receive と remove_all の変異を同時に入れたら、receive の方で止まり、remove_all の方が見えなかった。そこで分けた。
- 落ちた検査: 3つとも check-generated で、`just check` は回さず着地前に回した。
  - grammar sync（新しい名前空間を keyword-map に入れる）
  - quick-guide のサイズ上限（索引の行が1つ増えた）
  - docs のブロック数
  - ほかに、ctest の http_test がコンパイルできなくなっていた（消した ws_* を使っていた）。ローカルのどの段にも入っていなかった。/simplify が見つけ、CI より先に直せた。
- /simplify の指摘で入れたもの: http_test.cc を ws:: に移植、PageLink のセッション化、待ちの EM_ASYNC_JS を1つに、古いコメント、ハンドル種別の名前（owned/borrowed）。
- スキルへの気づき: 待ちの不具合を変異で入れると、テストは落ちずに止まる。プログラムとページが互いを待つため。ページとやり取りするテストには、一定時間で FAIL を出す見張りが要る。変異を同時に入れるのは、どちらかが止まる形のときは使えない。
