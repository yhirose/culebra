# 着地の前に ASan を待たない（CLAUDE.md の決まりの変更）

- 規模：小（CLAUDE.md の1文。スコープ none、ビルドも CI もなし）。
- きっかけ：user から「最近はいつも ASan で長い時間待たされて、開発効率が非常に遅くなっている」。asan.yml は誰も待たない形に移した（2026-11-17）のに、決まり（メモリを触る変更は着地前に ci/ で手で回す）と私の進め方（ASan を見届けてから報告・後片付け）が、まだ ASan を待っていた。
- 決めたこと：LLVM や V8 の型（マージ前は速い検査、重いサニタイザーはマージ後、赤なら戻す）にそろえる。メモリを触る変更も着地前に ASan を待たない。master の ASan が赤なら、原因の commit を戻して緑にしてから調べる。気づく仕組みは `just land` の警告のまま。
- 見送ったこと：ASan の run を最新だけにする（走っている run を止める形は、push が70〜90分より短い間隔で続くと結果が出なくなる。待っているものだけ置き換える形は、commit ごとの結果を失う）。ASan 自体を縮める手（キャッシュを分ける、gc-stress を分ける）は、待たなくなった後で足りなければ。
- スキルへの気づき：重い後処理を「マージを止めない」形に移したら、それを待っていた決まりと自分の習慣も同じ変更で洗う。
