# #32: 内側のブロックで同名の @value クラスを宣言して再代入すると、外側のクラスのメソッドが呼ばれる

- 規模: 小（ci/ 不要）。直列、担当なし。c1a1681f（worktree-issue-32、未着地）。
- 見込みと実績: 原因の特定に約30分、修正と確認に約40分。dev のビルド2回（2回目は fn_analysis.h を触ったので約5分）。
- 計画で効いたこと: issue の見立て（箱なしにするかを決める歩きが、クラス名を let の位置のスコープで引く）をそのまま確かめた。同じ穴で形の違う再現を2つ足した（標準ライブラリの Vector2 を内側で隠す、内側が @value でないクラス）。後者はリリース版で SIGSEGV。
- 直し方: FnAnalysis が resolve.h から `Name.new` の頭ごとに、その名前を宣言する名前のノード（Symbol::declared_at）を記録し、postfix_value_class はスコープで引いたクラスの名前のノードがそれと一致するときだけ採る。形の判定は parser.h の new_call_head 1つにまとめた（記録する側と読む側がずれないように）。
- 穴がクラス名だけだった理由: 先読みの答えのうち、後で「約束」として使われる（emit の時に再確認しない）のは、書き込みの右辺のクラスだけ。ほかの先読み（演算の被演算子、箱に戻す地点、束縛の IDENTIFIER）は、emit の時に本当の位置で引き直し、合わなければ箱ありに戻る。最初は「各束縛の名前ごとの歩きが内側の宣言で箱ありに倒すから」と考えたが、歩きは FUNCTION/CLASS_DECL の中に入らないので、その説明は誤り（/simplify の深さのレビューが指摘）。
- /simplify（4観点）: 最初の版はクラス宣言を symbol で後から突き合わせていたが、declared_at で足りると3観点が指摘して直した。
- 退行の確かめ方: 修正の前後で tests/ と examples/ の 715本の `-O0 --emit-llvm` を比べ、差分は新しいケースを足したテスト1本だけ。
- 落ちた検査: 新しい3件をそれぞれ単独のファイルにして、修正前に両レーンで落ちることを確かめた。
- スキルへの気づき: 先読みが「今の位置のスコープ」で後ろの名前を引く形は、名前ごとに歩きを持たない名前（クラス名、名前空間）でだけ穴になる。
