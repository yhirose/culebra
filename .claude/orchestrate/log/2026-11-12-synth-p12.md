# 2026-11-12 Synth P12: ステレオと入力・バス・Room の設計メモ

- 規模: 小〜大の間（実装なし、設計メモ）。担当は2人（一次資料の取得1、メモの独立レビュー1）。コミットはこの記録だけ。
- 見込みと実績: 見込みは読む30分、試作と測定30〜60分、メモ30分、レビュー約10分。実績はほぼ見込みどおり。dev は1回（新しい worktree の最初、ccache が効いた）。エンジンの試作は C++ の写しを scratchpad で直接ビルドし、リポジトリの dev は Culebra の試作にだけ使った。
- 測定と試作（どれもリポジトリに入れていない）: miniaudio の変換（モノのストリームとL=Rの2チャンネルが同じ標本）、エンジンの写しを2チャンネルにする差分（モノの音がビット単位で不変、ヒープ0、+2.8%）、Room の費用と長さ、`.pan` を式の層だけで書く試作（VM と `--jit`）。
- 効いたやり方: エンジンの写しを old/ と new/ に置き、同じ駆動のプログラムを2回ビルドしてダンプを比べる。ビルドは数秒で、devの278秒を回さずに「モノは不変」を確かめられた。P13 の実装でも、このダンプの比較をテストに移す。
- レビューで分かったこと（12件、すべて採用）: Synth の束を通す箇所（`ending`、`graph_of`、Voices のゲート、`SynthHandle.render`、`feedback`）、Proxy v2 の箱を含む式の `render` と終わり、`.pan` の位置の範囲と包絡、ブラウザの room（app.js のインパルス応答）、試作がバッファの途中から始まる Graph を通していないこと。レビュアーが記憶で書いた他の処理系の振る舞いは、一次資料がないので採らなかった。
- 計画の前提の訂正: Sound、Music、PCM はエンジンを通らず raylib で鳴り、すでに pan を持つ。P13 の対象はエンジンのストリームだけ。
