ソースの配置: 名前が意味しなければならないこと
==============================================

ファイルをどこに置き、何という名前にするか。以下の規則はどれも、
「名前が実態と逆のことを言っている」状態から出発しています。しかも
そのすべてが、検査ではなく読み手によって見つかりました。機械で押さえ
られる分は`tools/checks/check_header_naming.sh`と
`tools/checks/check_layering.sh`が持ちます。この文書はその規則が
何のためにあるかを書きます。

これらのファイルが実装しているアーキテクチャは[`vm.md`](vm.ja.md)、
メモリ側は[`memory.md`](memory.ja.md)です。英語版は
[`layout.md`](layout.md)。

## 1. ディレクトリが層である

`include/`には公開ヘッダ1本と10のディレクトリがあり、ファイルがどの
ディレクトリにあるかが、そのまま**どの層に属するか**です。includeは
読んだとおりに書きます（`<rt/value.inc.h>`・`<stdlib/http.h>`）。
`CMakeLists.txt`の`-I include`ひとつが全部を解決します。

| ディレクトリ | 中身 | includeしてよい先 |
|---|---|---|
| `base/` | エンジン非依存の土台: エラー型、`Runtime`のスロット、割り込み、書式、ハンドル表 | 上位は不可 |
| `frontend/` | 文法、パーサ、lint、関数解析、AST→AST変換、モジュール読み込み | `base` |
| `rt/` | 両エンジンが立つランタイム: 値表現、コレクタ、スラブ、`extern "C"`ヘルパー | `base` |
| `conc/` | isolate、channel、中立な`SendNode`、凍結共有値 | `base`・`rt` |
| `interop/` | C++のクラスとインスタンスを言語に束縛する | `base`・`rt` |
| `stdlib/` | namespaceごとのヘッダ、その下のカーネル、値表現に繋ぐ束縛層 | 下位すべて |
| `vm/` | バイトコード、コンパイラ、executor、セッション、埋め込みAPI | 下位すべて |
| `jit/` | LLVM loweringとcodegenコンテキスト | 下位すべて |
| `aot/` | `culebra build`がloweringの先で必要とするもの | `base`・`rt`・`frontend` |
| `cli/` | サブコマンド: test・fmt・lint・docs・init・repl・dap・toolchain | すべて |

積み重なりこそが要点で、それをゲートが保持します。逆流は3本あり、
それぞれ本数を記録してあるので、減ることしかできません:

- **`rt` → `frontend`（2）**: `rt.h`がパーサをincludeしているのは
  `peg::codepoint_length`の呼び出し1箇所のためで、必要なのはpeglibで
  あってパーサではありません。もう1本は`fn_analysis.h`で、`jit.h`が
  自分でincludeせず`rt.h`経由で`FuncInfo` / `FnAnalysis`を読んでいます。
- **`rt` → `stdlib`（1）**: `Tensor`はランタイムが知っている値なので、
  `Tensor`が独自のAOT軸を持つnamespaceでもある一方で、`rt.h`がその
  ヘッダをincludeしています。
- **`stdlib` → `jit`（1）**: `stdlib/bindings.h`の1メンバが
  `CULEBRA_JIT_ENABLED`の下で、LLVMモジュール上にランタイムのヘルパーを
  宣言します。

これがディレクトリ化で得られたものです。平坦だった頃は「このファイルは
どの層か」が読み手にしか答えられない問いだったので、**何もその答えを
拠り所にできませんでした**。新しい逆流は、コンパイルも通り全テストも
通る素の`#include`として入ってきていたのです。

## 2. `jit`はLLVMを意味する

`jit/`は、`<llvm/...>`をincludeするファイルが置かれている唯一の
ディレクトリです。両エンジンが共有するもの — 値表現、コレクタ、文字列、
dispatch、イテレータプロトコル、標準ライブラリ全体 — は構成上LLVM非依存
です。これは整頓の話ではありません。JITを持たないビルドでもプログラムが
動くこと（[`vm.md`](vm.ja.md) §9）と、WASM Playgroundが成立することが、
この性質そのものです。

長いあいだ、名前は逆のことを言っていました。`jit_value.h`・`jit_gc.h`
ほか8本が共有ランタイム**そのもの**で、`jit.h`がLLVM側で、両者を隔てて
いたのはアンダースコア1つだけでした。JIT無しビルドに何が残せるかを
判断する人は、結局ファイルを読むしかありませんでした。

`jit/`の外で`llvm::`を名指すヘッダが1本あります。上で触れた
`stdlib/bindings.h`の1メンバです。これは設計ではなく瑕疵で、このヘッダの
残りはエンジン非依存です。ゲートはLLVMを名指してよいファイルの明示リストを
保持し、リストは縮小のみ許され増えません。増えるということは、ツリーの
どこかがLLVM無しでビルドできなくなったということで、それは意識して
下すべき判断です。

## 3. `.gen.h`は生成物を意味する

生成物とは、レシピが書き直すファイルのことです。手で編集しても次の
`just gen-*`で失われます。この接尾辞はどれがそれかを示すもので、
**両方向に**正しくなければなりません。実際、両方向とも同時に狂って
いました:

- `grammar_blob.h`は`just gen-blob`が生成していたのに、そう名乗って
  いなかった。
- `canon_sigs.gen.h`はそう名乗っていたのに、生成元を削除したバッチ以降は
  手で保守されていた。

どちらも修正済みです（`frontend/grammar_blob.gen.h`・
`stdlib/canon_sigs_table.h`）。ゲートは「コミットされた全`.gen.h`に、
それを書くレシピが存在すること」と「生成器が`include/`配下に書く全パスが
`.gen.h`で終わること」を検査します。

## 4. `.inc.h`はヘッダではない

`rt/rt.h`は1翻訳単位ぶんのランタイムを、サイズの都合で9ファイルに割った
ものです。8本の`rt/*.inc.h`断片はその**本体**であって、意味のある
ヘッダではありません。自前のincludeでなく`rt.h`のincludeブロックに
依存しますし、1つの`extern "C"`ブロックが`rt/runtime.inc.h`で開いて
3ファイル先の`rt/iter.inc.h`で閉じますし、`rt.h`が固定順でincludeする
その順序は入れ替えると壊れます。

この制約は以前`rt.h`冒頭のコメントにありました。つまり、既にそこに
たどり着いた人しか読めませんでした。`.inc.h`はそれを名前に載せます —
Rubyの`.inc`が、インタプリタがテキストとしてincludeするファイルに対して
果たしているのと同じ役割です。ゲートは肝心な半分を強制します:
`rt/rt.h`以外はこれをincludeできません。

## 5. 標準ライブラリのnamespaceは1ファイル

C++で実装された利用者向けnamespaceには、`stdlib/`にその名前を小文字に
したヘッダが1つ対応します。`Http`は`stdlib/http.h`、`SQLite`は
`stdlib/sqlite.h`、`PEG`は`stdlib/peg.h`です。これはツリーの中で唯一
ドリフトしなかった命名軸で、新しいnamespaceもこれに従います。

同じディレクトリにありながらnamespaceそのものではないものが3種あります:
namespaceが必要とする補助ヘッダ（`Canvas`の背後の`image.h`・
`font_ttf.h`）、その下のエンジン非依存カーネル（`kernels.h`・`math.h`）、
そしてそれら全部を値表現に繋ぐ束縛層（`bindings.h`）です。C++でなく
Culebraで書かれたnamespaceは`src/preambles/<name>.cul`に置かれ、
最も小さいものは専用ヘッダを持たず束縛層の中に実装されています。

## 6. ファイルを追加するとき

- **stdlibのnamespace**: `include/stdlib/<name>.h`。加えてbinder・正典
  シグネチャ・AOT軸が要ります。全数は[`vm.md`](vm.ja.md)にあります。
- **ランタイムの断片**: それは`rt/rt.h`のものなので`rt/<what>.inc.h`と
  し、`rt.h`の順序付きブロックに加えます。自前のincludeが要るなら、
  それは断片ではなくヘッダです。素の`.h`にしてください。
- **LLVM loweringだけが使うもの**: `jit/`に置きます。他所に置いてそこで
  LLVMに手を伸ばすのは、細部ではなく判断です。
- **生成物**: それを所有する層の下に`<name>.gen.h`として置き、書く
  レシピをjustfileに、古くなったら落ちる`check-`レシピも用意します。
- **すべてに共通**: 抱えられる最も下の層に置きます。上を指すincludeは
  `just check-layering`で落ちます。これは`just test-dev`の中で走ります。
