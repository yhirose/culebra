# linz — 線形型の型検査器

「線形型」を持つ小さなラムダ計算の型検査器。すべての値は`lin`（必ず
ちょうど1回使う）か`un`（何回使ってもよい）のどちらかに印がついていて、
プログラムを検査するとは、その印に嘘がないことを証明することを意味する
——`lin`な値を2回読んでも、一度も読まなくても型エラーになる。
[rust_zero](https://github.com/ytakano/rust_zero)の`linz`（`ch09/linz`）
からの移植で、元は[nom](https://github.com/rust-bakery/nom)による手書き
パーサと、可変で深さ索引付きの型環境スタックだった。言語そのものと
検査アルゴリズムは`lin.cul`自身の冒頭コメントと各所のコメントを参照。
このファイルは、移植で何が変わったかについて書く。

実行方法:

```
culebra examples/linz/linz.cul examples/linz/samples/ex1.lin
culebra examples/linz/linz.cul --ast examples/linz/samples/ex1.lin
```

`samples/ex*.lin`は型が付き、`err*.lin`は線形性か型のどちらかの理由で
拒否され、`parse_err.lin`はそもそも構文エラーになる。16本とも元のRust
プロジェクト自身のサンプルをそのまま使っていて、`test_lin.cul`が移植版
の検査器をこの16本全部に対して確認している。

## Rust版から変えたところ

- **手書きパーサの代わりにPEGを使った。** 元の`parser.rs`のdocコメントに
  書かれたBNFは、ほぼそのまま`PEG`の文法に写せる（`docs/stdlib.md`の
  §34参照）。本当の違いはキーワードの語境界の扱いだけ——`%word`
  （`PEG`／cpp-peglibのディレクティブ。同じ手法は`examples/pl0/pl0.cul`
  の文法にもある）を使うと、文法中の引用リテラルはすべて、自分を接頭辞
  に持つ長い識別子にはマッチしなくなる。元のRust版は「1語読んでから
  文字列比較する」という組み方でこれを自然に得ていた。

- **環境を不変にして、戻り値として持ち回るようにした。** 元の`TypeEnv`
  は2本の可変・深さ索引付きスタック（`lin`用と`un`用）で、push/popを
  明示的に行い、`un`な関数閉包の制限された見え方のために`mem::take`で
  退避してあとで戻す、という一手間もある。`lin.cul`の
  `typing(node, env) -> (type, env')`は、環境を受け取って、書き換え
  ずに「出てきた後の環境」を返す形にした——この設計が構造的に何を
  もたらすかは`lin.cul`内の「`Why an immutable environment`」に書いた。
  `examples/hm/README.md`では、同じ問いを別の形の型システム
  （検査ではなくHindley-Milner推論）に対しても立てていて、「この形が
  どこまで一般化するか」は「見た目ほどには一般化しない」という結果に
  なった。

- **キーワードを予約語にした。** 元のRust版の分岐は`let`/`if`/`split`/
  `free`/`lin`/`un`しか特別扱いしておらず、裸の`true`・`false`・`bool`
  は素通りして**変数への参照**としてパースされてしまう（正しい
  プログラムではこれらは必ず`lin`/`un`修飾子の後にしか現れないので、
  パーサ側は特別扱いしていなかった）。`lin.cul`の`RESERVED`はこれを
  完全に塞いでいて、9つのキーワードはどれも変数名になれない——
  「位置によってキーワードだったりそうでなかったりする」より単純に
  説明できる。

- **エラーがより正確になった。** 元のRust版はソース上の位置情報を
  完全に捨てている（`main.rs`は`AST:\n{ast:#?}`と素のメッセージを
  出すだけ）。`lin.cul`は`PEG`ノードの`line`/`column`を最後まで持ち
  歩く（`pl0.cul`の`fail(node, msg)`という書き方をそのまま流用した）。
  さらに、元のRust版が1つに混ぜてしまっていたエラーを分けている——
  `err5.lin`はifの両分岐の**型は一致している**が、消費した`lin`変数が
  食い違っている例なのに、元のRust版はどちらの場合も「thenとelseの
  式の型が異なる」と報告する。型は合っているので`err5`に対しては
  誤解を招く。`lin.cul`はそれぞれに別のメッセージを用意した。

## 隣にあるもの

`examples/hm`は同じ種類の言語を別のやり方で検査する——著者自身が
書いた注釈を確認するのではなく、Hindley-Milner推論で型を組み立てる
——`lin.cul`の形がどこまで一般化するかを確かめるために書いた。
結論としてはほとんど一般化しなかった。理由はそちらのREADMEを参照。
